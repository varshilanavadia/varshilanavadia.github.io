How to use this document
One system, eighteen sections
Everything here is settled. Rules marked derived were reasoned from a ratified decision rather than taken directly from one, and the reasoning is on the page with them, so an argument can always be told from a ratification. §18 records the eleven decisions taken on 24 August 2026 and what each one displaced.
What it governs. The three site files, both specification documents, and any exploration that has become the record for a decision — anything, in short, that outlives the turn it was made in. A sketch may disagree while it is still a sketch; the moment somebody reads it for an answer, it follows.
If something is not named here, that is a gap in the system rather than a licence to decide locally. Name it, with the arithmetic, in the section it belongs to.

01 · Foundations
Type system · 02
Two faces, one job each
Figtree carries everything read as prose or as a heading. IBM Plex Mono carries records: strings a machine produced or a person typed, identifiers, type names, and figures that align down a column. Nothing else is licensed for this project, and a third face is a decision, not a preference.
Face
Weights
Remit
Figtree
400 · 600 · 700 · 800
Prose, headings, labels, buttons. Four weights, and 500 is not among them — one instance existed and was corrected.
IBM Plex Mono
400 · 700
Records only, and only where §01’s five groups permit. 700 is used by two roles: the field index and the stat value.
The x-height match
Mono set beside Figtree at a shared token reads larger, because Plex’s x-height is the greater share of its em. Every mono run therefore carries font-size-adjust: 0.5, which normalises it to Figtree’s own ratio. Measured with both faces loaded: Figtree 0.500, Plex 0.516. The value is Figtree’s number, not an average, so Figtree is the one that never moves.
Measure webfonts with the face awaited. document.fonts.ready resolves before a stylesheet has registered its faces, so a probe that trusts it silently measures the fallback. Await document.fonts.load() for each weight, and measure a deliberately absent family alongside as a control: if the two agree, the real face never arrived. Both numbers above were taken that way.
Six faces, and no more
Four Figtree weights and two mono weights is the whole request, in every file. A fifth Figtree weight is a new decision; adding one silently is how a system stops being one.
01 · Foundations, continued
Type system · 03
The five things mono is for
Mono is a register, and a register needs a boundary or it becomes decoration. These five groups are the whole of it.
#
Group
What it covers, and the roles that carry it
1
Verbatim machine strings
Token names, CSS values, code, paths. Mono value, Inline code.
2
Structured identifiers
Short codes where the shape of the characters is the information. Field index.
3
Type classifications and typed input
Machine type names, answers a person typed, an email address. Field type, Mono answer.
4
Figures that align down a column
Distances, durations, paces, dates in a rail. Activity figure, Date rail.
5
Display figures
Figures large enough to read as instrumentation, and a typed identifier that is the primary action of its block. Stat value, the contact address. The only group permitted above t0.
The boundary
Mono never carries prose, headings, block-naming labels, or anything that wraps. Mono answer is the single exception on wrapping, capped at three lines. Only group 5 may sit above t0 — the movement figures at t3, and the contact address at t2, which is the whole of it. Mono annotating Figtree takes --ink-3, the softening rule, so a record never outranks the prose it belongs to.
Why group 4 earns its place, when tabular-nums was already available: tabular figures align digits but not the letters beside them, and these figures carry units — mi, bpm, /100m. In Figtree a column of them stays ragged. Mono aligns the whole string, and the unit is part of the record.

If a new design needs something this list does not name, that is a gap in the system rather than a local decision: name it here. The last four were named in the two days to 25 Aug 2026: a subtitle under a row title, a link outside prose, an error message and a counter.
04 · The label group
Type system · 08
Four label roles, three axes
All four share one form: uppercase, --lh-normal, no wrap, and a size inherited from the block. They differ on three axes, and each axis means something. Tracking says what the label does — 1px names a block, 0.5px annotates a value. Weight says whether it is structural. Ink says whether the label is itself information or an annotation on something else.
Eyebrow
700 · 1px · --ink
Names a block at heading weight. A heading element.
Block label
600 · 1px · --ink / --ink-3
Names a block, but must not compete with the title under it.
Column header
700 · 0.5px · --ink
A table column. Always th.
Label
600 · 0.5px · --ink / --ink-3
Annotates a value.
Retired names
* The one case that is not uppercase: a tag. Its text is content the author typed, so uppercasing it changes words rather than styling them. Settled 24 Aug 2026.
Kicker, Meta label, Status label and Micro label are gone. Kicker had zero uses in the site — all eighteen were in the specification documents’ own chrome. The others differed from a surviving role on one property, twice on ink alone.
Why the size is inherited
The old declaration put every label at t-1. No label in the site is at t-1: the wireframe runs t0 and t-1, the button document t-2, and t-1 was the specification documents’ own density written into the role as though it were the system’s. Inheriting the block’s size is what the site already does, and it makes the same label legible at three densities without four more tokens.
05 · Leading
Type system · 09
Leading follows the role, not the size
Five tokens, each belonging to a class of role rather than to a band of sizes. A 39px feature title and a 25px row title take the same token because they do the same job; a 20px lede and a 20px date rail take different ones for the same reason.

Two rules that follow from it
A literal leading value is a defect unless it is ratified in §15. There is exactly one ratified value, the sticky bar’s 1.2, and it is load-bearing on a tap target. Second: line-height: 1 is not leading, it is an alignment fix, and it belongs in a layout rule rather than a type declaration — prefer align-items: first baseline on the container.

05 · Measure
Type system · 10
Prose is measured in characters
Leading sets the distance between lines; measure sets how far each one runs. Prose takes one token stated in characters, so the count holds at whatever size the role is set. Headings keep a cap in rem, because a heading’s cap fits it to the page column rather than to a reading measure, and ch on a bold display line is a poor proxy for anything.
Cap
Roles
--measure  46ch
Lede, supporting note, caption, and all running prose in a document.
56.25rem
Page title.
47.50rem
Document title, section heading.
row-bounded
Feature title, body / excerpt. The row supplies the width; there is no cap.
The arithmetic
Measured with Figtree loaded: 1ch is 0.641em, the average character advance 0.422em, so one ch buys 1.52 characters. 46ch is therefore about 70 characters at any size, inside the 45–75 target. The band in ch is 30 to 49. One token serves t0 and t-1 alike, because ch scales with the type and the character count does not.
This replaced two rem caps that were the same measure in disguise. 47.5rem at t0 is 38em and 38.75rem at t-1 is 38.75em — 90 and 92 characters, both well past the band. An earlier draft of this rule declared 54ch, computed from a probe that had not actually loaded Figtree and so measured the fallback; 54ch is 82 characters. §01 carries the method that prevents it happening again.
Why body / excerpt takes none
It is a truncated preview rather than reading text: three lines, then an ellipsis. Its width comes from the row — to the image where the entry has one, to the row’s own edge where it does not, the same edge the title runs to.
05 · Rhythm
Type system · 11
Block gaps are multiples of the body line box
The type scale and the spacing scale used to derive from nothing in common, so vertical rhythm was decided by eye every time. They meet at one number: t0 at --lh-body makes a 30px line box, and that is what separates one block from the next. Settled 24 Aug 2026.

The rule
Anything that separates blocks takes s4 or s5, so every block boundary is a whole number of body lines and two columns of blocks stay level down the page. Anything inside a block takes s0 to s3, which answer to the elements around them rather than to the line box. The old values this replaced were 40 and 64 — close enough to 30 and 60 to look deliberate, and derived from nothing.
What it costs
Every block gap in the project tightened by 10px and every section gap by 4px, in one pass across the site files and this document. Nothing else moved: the six names are unchanged, so no reference had to be rewritten. The 24px step is now close to 30 — that is the seam, and the rule above is what tells them apart.
06 · Case, tracking and numerals
Type system · 12
Tracking follows case, not taste
Tracking

All body, all headings from t1 to t4. No optical tracking by feel.

Hero name
Permitted at t6 only, which is the hero name and nothing else.
Case
Uppercase is the label group and the wordmark. Nothing else — no uppercase prose, no uppercase headings, no uppercase buttons. Button labels are sentence case, which is why they are the exception in the tracking table. Above t-1 the only caps in the system are the wordmark.
Numerals
tabular-nums wherever figures align down a column, sit in a table, or change in place — stat values, activity figures, date rails, field indices, and any rem or px column in a specification table. Proportional figures everywhere else, including prose. A figure that changes in place without tabular numerals makes the line jump, which reads as a layout bug rather than a number.
One more, for records
Records never hyphenate and never wrap: white-space: nowrap on every mono role except mono answer. A broken token is a different token.
07 · Wrapping and overflow
Type system · 13
Clamping is a grid rule, not a text effect
A clamp exists so a repeating row keeps its height. That is the only reason it is permitted, and it produces the eligibility rule: only a role inside a repeating row may clamp. Prose in a document never clamps; it wraps to its measure and runs as long as it runs.
Role
Clamp
Why
Feature title
1
A second line pushes the row off the grid.
Body / excerpt
3
Authored as a two or three line summary; the clamp is insurance, not a truncation strategy.
Mono answer
3
The one mono run that may wrap.
Row title
none
Each is the only variable-height thing in its entry, so nothing beside it has to stay level.
Lede
none
One instance per block, and never truncated.
The mechanism, and how it fails
Four properties travel together: display:-webkit-box, -webkit-box-orient:vertical, -webkit-line-clamp:N, overflow:hidden. They fail two different ways. Miss the display or the orient and the clamp does not fire at all, which is obvious. Miss the overflow and it fires but paints the remainder outside the box, over the row below — while every measurement of the grid still reads as healthy. That second one is why the four are declared as a set.
A clamp only holds a grid while it is the tallest child. The moment something beside it grows taller, the row is governed by that instead and the clamp is decoration. Hence the cap in §15 on tags per writing row.
Two prohibitions
No text-overflow inside a clamp: the clamp draws its own ellipsis and the property is inert. No text-wrap: balance on a one-line clamp: there is nothing to balance. Elsewhere, balance belongs on headings that wrap and pretty on prose.

The three rules
Ratios are stated against the darkest named ground, --sheet-alt, so a number that clears there clears everywhere. Hairlines are rules, not ink — a 1px line is never --ink-3; if it looks like a rule it takes a rule token. A ground darker than --sheet-alt takes the inverted set, which the next page derives. An unscrimmed image still carries no guarantee, and no type.
Pure black is not in the system, with one ratified exception — the bracket button’s label, where a difference blend makes #000 arithmetic rather than a choice. A file that leaves body text at the browser default inherits #000, which is darker than anything declared here and reads harder; every file sets color: var(--ink) on the body.

08 · Type on a photograph
Type system · 16
Type on a photograph needs a scrim, and here is how much
An image has no guaranteed luminance, so the worst case is a white pixel under white type — a ratio of 1:1. A scrim of --ink at a stated opacity fixes it, and the opacity is arithmetic rather than taste: compositing 60% #111 over pure white gives #707070 — 0.6 × 17 + 0.4 × 255 — and white on #707070 is 4.95:1, so #fff clears 4.5:1 over any image. At 70% the composite is #585858 and the ratio 7.11:1.
Scrim

4.95:1

70% --ink

The scrim is a property of the type, not of the picture: it goes behind the text block, not across the whole image, so a portrait stays a portrait. Activity figure declared --sheet until 25 Aug 2026, which was always a stand-in — it is --ink-inv over a 60% scrim.
09 · Interactive states
Type system · 17
Four states, and one carve-out
State
Declaration
Link, at rest
--ink with a 1px --ink-3 underline. The underline is the affordance; colour is not used to signal a link.
Link, hover
The underline moves to --ink. Nothing else changes — no colour shift, no weight shift, no motion.
Focus
A 2px --ink outline at 2px offset, on :focus-visible only, so a mouse click never draws one.
Row hover
The row ground becomes --sheet-alt. Text ink does not move.
Placeholder, disabled
--ink-3. Entered text moves to --ink, which is the only signal that a field has content.
The carve-out: the sticky bar’s four nav labels
They draw no focus ring. Their focus indicator is a pair of brackets that sits on the focused label, which is a stronger signal than an outline on a 44px target and is part of the bar’s design rather than a substitute for it. The wordmark beside them keeps its ring. Scope is those four labels; everything else in the project takes the ring in the table above.
Two conditions the carve-out depends on, both of which have to hold if the bar is ever redesigned: the brackets must track focus rather than scroll position while focus is inside the set, and the labels must remain real links with real destinations, so that nothing is announced as interactive that cannot be reached.
09 · Buttons
Type system · 18
One button, and three states it does not have yet
The project has a single control: the bracket button. Two corner brackets at rest, drawing outward on hover while a black spill fills in behind them and the label inverts per pixel as the edge crosses it. Its type is Button label — t0 · 600 · ls 0.5px, sentence case, on a fixed 56px control with 28px of side padding, and the label never wraps.
The label is pure black, and that is deliberate
§08 says pure black is not in the system. This control is the exception, and it is arithmetic rather than preference: the label is white type in difference blend mode, so the two operands decide the result and there is no third colour to pick. White over the white plate gives #000; white over the black fill gives --sheet. Both land exactly on declared values. Against an --ink fill the same blend would give --rule-faint on the fill and #000 on the plate — neither of them declared. Ratified in §15.
What is specified, and what is not
State
Declaration
Rest
Brackets only. No fill, no full outline. Label at #000.
Hover
Brackets close to a box over 60% of the duration; spill fills behind; label inverts per pixel. Contrast is 21:1 at both ends — the crossing is the only ambiguous moment, so the transition stays under 400ms.
Focus
Not specified. The hover animation is not a focus indicator. §09’s ring is the default until this is designed.
Active
Not specified. A 2px inward nudge is the intended direction.
Disabled
Not specified. 35% opacity on brackets and label, no hover, is the intended direction — and it needs a contrast check, since 35% of #000 on white is 2.4:1.
There is no second button. No secondary, no destructive, no icon-and-label, no size other than 56px. That is a gap in the system rather than a licence: a design needing one names it here first. And the hover treatment must sit behind prefers-reduced-motion — the reduced variant is an instant fill, which keeps every state legible.

The failure to design against

If it must also print on A4
A4 is 794 × 1123px — narrower and taller than letter. A layout built to letter’s 688px column reflows on A4 and can overrun vertically. If a document has to serve both, lay it out to a 674px column — A4’s width less the same margins — and it will fit either sheet.

13 · Long-form, continued
Type system · 24
How the article page is built
derived
Three rules, all derived from the roles above rather than from a design.
The measure governs the column
An article is one column at --measure — 46ch, about 70 characters, 590px at t0. Headings, quotes, lists and footnotes all take the same measure, so the left edge never moves and the right edge is ragged at the same place down the whole page. Figures may exceed it; type may not.
The heading ladder stops at three levels
Article title, article heading, subhead. That is h1, h2, h3, and it matches the rule the rest of the system already follows — headings stop at h3 because nothing on any page in this project is nested deeper. A fourth level is a sign the piece should be two pieces.
What is deliberately absent
No pull quote, no drop cap, no small caps. Figtree has no small-cap axis, so small caps would be synthesised and would break the x-height match that §01 exists to protect. A pull quote duplicates the blockquote at a larger size and earns nothing; if a line deserves that emphasis it is the lede.
The one thing left open
The article page repeats the writing row’s rail — a date and a read time in a column beside the title. Whether those become mono, as group 4 of §01 would suggest for figures that align down a column, or stay in the label group as they are today, is still open. It is the only long-form question that is not answerable from the existing system, and §18 lists it.

Type system · 25
The scale does not change. What may use it does.
derived
Every file is pinned to a 1440px minimum width today, which fails 1.4.10 Reflow at a 320px-equivalent width and 1.4.4 Resize Text at 200% zoom. This is the type half; the layout half is design work, and §18 says which parts of it are still unbuilt.
Two anchors, no breakpoint set
1440px is the design width and 320px is the floor. Between them a display role interpolates with clamp() on viewport width, so there is no breakpoint to maintain and no width at which the page is untested. 16 · Elements
Type system · 28
A role is not an element
Which element carries each role is settled, and the table lives in Semantic Mapping §04 rather than here: 25 roles against their elements, each citing the decision it follows from. Restating it in two documents would rebuild exactly the divergence this document exists to prevent. What belongs here is what the column of elements shows once it exists.
01
A role is not an element
Row title is an h3 in the timeline and the writing rows, and a label in the contact form. Label spreads widest of all: dt, time and a. The role fixes the type; the context fixes the element.
02
Heading levels follow depth and stop at h3
Hero name is the h1, the four section names are hidden h2s, and every repeating title is an h3. Long-form takes the same three levels.
03
The element carries no size
Three roles map to h1 — the hero name at t6, the document title at t5, the page title at t4. An h1 is not a size, and nothing in §03 changes if the element does.
04
The three hidden roles are the mono ones
Field index, field type and the retired micro label are all aria-hidden. Mono marks a record, and a record read aloud is noise. The mono register and the accessibility tree drew the same boundary without either being designed for the other.
